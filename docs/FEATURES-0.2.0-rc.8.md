# rc.8：共享功能与记录排序（验收候选）

## 宿主接入

继续使用平台唯一 session、ACK/outbox、IndexedDB 和资源/评论服务。包不建立连接或自动保存。本轮不修改文件交换格式，也不声称高级规则的 XLSX 往返已经验收。

仅服务端创建**新的隔离文档**时显式使用：

```ts
import {createExlsxBaseline, EXLSX_FEATURE_SCHEMA_VERSION} from '@online-office/univer-sheet/yjs'
const recovery = await createExlsxBaseline(snapshot, epochId, {
  schemaVersion: EXLSX_FEATURE_SCHEMA_VERSION, // 3
})
// 原 baseline 与原始 update 原子保存；每个页面恢复这同一份 recovery。
```

其他恢复/注入 API 不变：`restoreExlsxDocument`、`createExlsxCollaborationSession`、`session.ready`、`session.onLocalTransaction`、`session.applyUpdate`、`checkpoint`、`dispose`。工具栏读取 `session.capabilities`，不是宿主猜测私有命令名。默认 schema 仍为 1。旧 `EXLSX_COLLABORATION_CAPABILITIES` 常量只概括 schema 1。

已有在线文档升级必须由宿主协调停止旧 epoch 写入、处理所有未确认修改，再准备新谱系；本包不会替宿主自动升级。`univer-commands-v3` 实验性旧日志不是本轮 schema 3。

## 实际矩阵

| 能力 | schema 3 状态 | 语义与限制 |
| --- | --- | --- |
| 单元格内容、样式、公式文本 | 支持 | 延续寄存器；同格内容整体裁决，不是字符级合并 |
| 合并/取消合并 | 支持 | 顶部合并菜单或 `handle.setMerge(remove?)`；不清空覆盖格的原内容；已有重叠合并需先取消 |
| 冻结至首行/首列/选区 | 支持、共享 | 不属于权限锁定；整组冻结状态裁决，重载保留 |
| 筛选 | 支持、共享 | 原生筛选范围和条件；过滤结果是派生数据，不独立提交 |
| 排序 | 有限支持 | `handle.sortRecords({ascending,header?,column?})`；按选区行、选定列排序**全部列的记录**，空值放最后，稳定排序 |
| 排序公式/合并区 | 明确禁止 | 含公式的文档，以及排序行与任意合并相交，操作前报错；没有宣称公式引用自动改写 |
| 条件格式 | 支持规则状态 | 原生新增/修改/删除/优先级；规则组共享、撤销、投影与重载；复杂公式规则计算仍取决于引擎 |
| 数据验证/下拉列表 | 支持规则状态 | 原生面板、列表选择；新增规则是内容动作，不能把点“新建规则”当作零提交的打开面板 |
| 行列插删/移动、扩展、手动大小/隐藏 | 协同禁止 | 不提供一般结构 CRDT；自动行高是派生显示，不等于支持共享手动尺寸 |
| 工作表增删/复制/重排/重命名 | 协同禁止 | 独立单机演示不代表协同支持 |
| 图片、图表、高级数据表 | 协同禁止 | 未交付位置/引用模型及并发保证 |
| 任意图片/附件内联、完整 IME/剪贴板全集 | 待实现/待验收 | rc.7 基础用户节点及局部样式不代表已全部交付 |

不兼容的上游原生合并和任意局部排序入口在包内隐藏并拦截，使用本包顶部动作。下拉面板和条件格式是原生面板，不是静态按钮。

## 并发与永久评论

- 行身份是 baseline 行记录 ID。排序只改变“显示槽位 → 稳定记录 ID”的稀疏排列，不转发数字坐标历史命令；单元格内容寄存器与排列独立。因此一人排序、一人离线编辑旧位置，编辑跟随原记录。
- 原生输入草稿绑定原记录；编辑时暂缓覆盖当前输入格的远端显示投影，提交/取消后补齐，不用远端值刷新掉本地未提交文字。编辑过程中读取原生视图快照可能看到暂缓的显示格；需要权威内容时使用 Node/model 投影 API，不把编辑中视图快照当新 baseline。
- 同表两个排序并发：整个排列寄存器确定性裁决；不是合并两种排序意图。合并集合、筛选状态、条件格式规则组、验证规则组各是一个独立寄存器。同一组并发按 Yjs 胜者保留整组，不逐条合并规则；不同组与内容独立合并。
- 合并不删除被遮盖格内容，所以不制造“合并时远端编辑被清空”的语义。排序与合并重叠时拒绝，未实现两者任意并发意图融合。
- 排序仅移动单元格记录；手动行高和格式规则范围仍按网格槽位，不跟随记录。筛选、验证、条件格式均使用固定轴 ID 范围。**评论明确跟随记录**。
- `captureCommentAnchor()` 在 schema 3 返回 version 3、epoch、工作表 ID、精确 `rowIds` 和列边界。排序后原范围可能变成不连续区域，使用 `resolveCommentAnchorRanges(anchor)` / adapter `resolveCellAnchorRanges` 获取全部矩形。旧的单范围 `resolveCommentAnchor` 只返回第一个矩形，不能用它包围所有记录。
- 评论装饰层绘制全部矩形并去重候选 ID，不写入单元格样式。评论 UI、正文、解决状态与权限仍归宿主。
- 撤销只跟踪本 session 的事务；后来同组远端写入不被本地撤销覆盖。撤销历史不跨刷新持久化。
- 普通 checkpoint/`compactExlsxRecovery` 保持同一不可变 baseline、epoch 和记录排列；不能把最新投影当旧 epoch baseline。异 epoch 评论拒绝定位，新谱系评论映射仍需宿主显式处理。

## 规模与性能

新文档示例 220 行 × 26 列。一次排序最多 10,000 行、250,000 个单元格；累计稀疏排列最多 10,000 条。单条永久评论最多精确记录 10,000 行。每类规则最多 1,000 条，每条最多 1,000 个范围，序列化规则组最多 1,000,000 字符，嵌套深度 30；越界拒绝。

记录反向定位为每个不可变排列建立一次索引，随后 O(1) 查找；排列校验避免逐行扫描。排序仍需重投影涉及的整行数据，不能当作无限大表的免费操作。基础增量接收验证不做每次全量 workbook 序列化。浏览器滚动/内存数字必须看对应实测报告，不能把模型测试时间当成用户操作延迟。

恢复时先投影记录顺序再应用规则，最后重算派生筛选；内容投影后也重算已激活的筛选，不能复用排序前的隐藏行缓存。重算不产生内容事务。增量单格更新只校验本次变化的排列，不反复校验整张已排序表。

## 示例与验收边界

`examples/features-acceptance.tsx` 仅导入公开包接口，入口 `?acceptance=features&room=隔离测试名`。两页使用同一链接。提供原生工具栏、宿主评论、只读、模型只读检查、checkpoint 保存。BroadcastChannel 只是测试传输，不是生产 outbox/ACK 实现。

自动化模型测试：`src/sharedFeatures.test.ts` 覆盖各类状态更新、双会话、重复 update、远端零回声、undo/redo、checkpoint/压缩、评论连续/不连续排序、离线/草稿记录身份及非法数据；`src/sharedFreeze.test.ts` 与 `src/session.engine.test.ts` 覆盖真实引擎冻结。安装产物的实际浏览器结果和截图随唯一 hash 的外部验收报告提供；未通过的场景不得标为通过。断线、重试 ACK 与真实平台离线队列仍需联合验收。
