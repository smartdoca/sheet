# rc.6 · 双行工具栏与大数据协同优化（部分交付）

本版**不是原子内联富文本/结构 CRDT 交付**。当前正式协议仍为 `exlsx-cell-registers / schemaVersion=1`，baseline/epoch/ACK/outbox 边界不变。不能将下面的分期设计当作已导出接口。没有清空文档、浏览器缓存或未确认队列。

## 本轮已实现

- 默认 `toolbarLayout='two-row'`：按基础编辑、文字、颜色/边框、对齐、数字、插入/公式分组，每组内部两行。宽屏紧凑居中，窄屏按优先顺序将整组放入有名称的更多弹层；弹层在 portal 中，不被表格容器裁剪。`simple/classic/collapsed` 保留。
- 宿主 `menus` 的 ribbon 动作在末组显示；正式 icon、ariaLabel、tone、动态 visible/enabled 与独立评论权限继续生效。评论推荐 `tone:'amber', iconOnly:true, enabled: ctx=>!!ctx.selection, requiresEditPermission:false`。不默认添加全文评论或点格悬浮评论按钮。`toolbarEnd` 为低层宿主插槽，其业务权限由宿主负责，优先使用 menus。
- `handle.getFormatState()`：直接读模型，不读 DOM/序列化快照；selection/style/mixed/complete/canUndo/canRedo。格式汇总最多 4096 格，超限明确 complete=false，不假称全选区格式一致。按钮由选区/内容命令更新，无 250ms 轮询。
- `handle.setCellNumberFormat(range|null, pattern)`：原生命令→样式寄存器；独立 API 避开未协同的原生 numfmt 资源突变。常规/文本/数字/日期时间/货币/会计/百分比，以及简单数字格式的小数位。复杂自定义格式的小数位调整报错，不猜测改写。
- 下划线和删除线独立切换，不用会同时清除两者的原生 `setFontLine('none')`。边框颜色独立于填充色。
- 删除普通 UI 的 JSON 下载入口。`downloadSnapshot` 仅保留内部恢复用途，不应暴露给普通用户。XLSX 沿用 rc.5 的纯转换器与 warnings，新基线导入、纯读导出。
- 原有 `@` 按键整格回调不再拦截用户输入；`onMentionRequest` 不会被调用。`setCellObject` 整格对象写 API 明确报 UNSUPPORTED_OPERATION，不冒充光标位置内联插入，也不覆盖已有文字。已有 custom 数据不删除，显式 legacy renderer 可读展示，但不是原子内联验收。编辑态不会交给旧整格粘贴回调处理。
- legacy 对象展示：无 renderer 时零扫描/零定时器；有 renderer 时建立稀疏索引，内容变更按受影响格更新，视口变化只重定位对象，不再每 200ms 导出完整快照。单个 renderer 异常局部显示名称与重试，不阻断工作簿。

## 协同性能实现与边界

旧路径：每一条 applyUpdate 都 `encodeStateAsUpdate(全 Doc)` → 新建候选 Doc → 全量解码与扫描全部寄存器 → 销毁。代价与累计修改格数及 Yjs 历史有关，单格编辑也付全表成本。

新路径：第一次接收建立**隔离校验副本**，之后同步合法本地/远端/撤销增量，只检查本次实际变化寄存器以及 metadata/集合边界。只有校验通过才 apply 到宿主 live Doc。任何拒绝都销毁校验副本，下次从未污染的 live Doc 重建，避免非法更新或悬置依赖污染后续验证。它不是第二条协同连接或保存链路。

本地样式 ID 解析新增可选 `CollaborationContext.getStyleById`，默认 runtime 直接查样式表，不再每格调用 getSnapshot；自定义 runtime 无该接口时每批至多读取一次快照。校验不取消 schema/epoch、未知字段、JSON、原子内容、越界和 5 MiB live update 限制。

基准可运行 `EXLSX_BENCH=1 yarn test src/session.performance.test.ts`。10,000 / 100,000 已修改寄存器，两副本，同一组单格编辑；比较旧全量复制/扫描与新热接收路径，单独列首个冷接收，重复更新无回声。旧参考未执行更深字段语义校验，比较偏保守。原始结果在 `artifacts/performance/session-benchmark.json`。不能把 0.x ms 校验延迟当作整页输入/绘制延迟。

代价和未完成优化：

本机 Node v24 复测（2026-09-13，20 次热更新）：

| 已修改格数 | 旧复制/扫描 p50 / p95 | 新热接收 p50 / p95 | 新首次冷接收 |
| --- | --- | --- | --- |
| 10,000 | 22.25 / 29.36 ms | 0.129 / 0.217 ms | 21.03 ms |
| 100,000 | 200.97 / 253.23 ms | 0.176 / 0.202 ms | 175.31 ms |

两组回声均为 0。进程堆增长分别约 45 / 355 MiB，包含测试夹具、参考复制和未强制 GC 的垃圾，不是优化算法的独立峰值，不能用于承诺客户端内存上限。

- 首次校验副本构建仍是 O(累计 Yjs 状态)，多一个 Doc 会增加常驻内存；错误后重建也有同等成本。baseline clone/hash、checkpoint 编码和初次全投影仍是全量操作。
- 单次大粘贴、复杂公式重算、超长富文本、超多 legacy 对象、长期撤销历史仍可能占用主线程/内存。没有宣称百万格或任意对象密度无卡顿。
- 接收上限 5 MiB/条；完整 checkpoint 与 baseline 不受此网络增量限制。需要由平台限速、分批并设置服务端内存预算。默认 XLSX 限制仍是 10 MiB 文件、32 MiB 解压、100,000 存储格、20,000 行/256 列、估算 256 MiB（不是硬堆限制）。
- 本版原子内联节点允许数 **0**；对象上传/重试/安全 URL/稳定插入目标等原子内联资源链路未提供。不能对没有实现的能力编造容量指标。
- 浏览器性能示例 `examples/office-acceptance.tsx?large=1` 使用 100,000 有值格、两表，显示双 RAF ready 耗时；滚动测量记录 rAF 间隔，heap 为 Chromium 进程观测，不等同独立峰值/跨机器 SLA。确切结果与截图在发布记录。

## 明确分期（不是已发布 API）

1. **本轮 P0：** 已交付固定结构协同热路径优化、事件驱动双行工具栏、真实性门禁、交换与性能证据。缺失项保持禁用。
2. **P1 原子单元格内联：** 新 codec/schema 提案，仍可选择“整格内容寄存器确定性胜者”，不要求字符 CRDT、不宣称字符级合并。需要同时交付原生单元格编辑器与公式栏的节点适配、文本范围/光标 API、复合普通 runs + 原子节点、插入事务、validator/投影/undo/checkpoint/剪贴板。禁止仅放开 p.customBlocks。未实现前 atomicInline=false。
3. **P2 结构与资源：** 稳定 sheet/row/column ID + 有序结构 CRDT；删除胜出规则、部分评论范围收缩/全删 orphan、公式引用、复制新身份和资源引用。然后共享冻结/隐藏（或明确独立个人视图协议）、浮动绘图位置和稳定 assetId。与在线客户端协调新 epoch，不复用旧队列。
4. **P3 图表/高级规则：** 稳定范围引用、图表类型与样式、源数据更新、并发编辑与撤销；规则对象 CRDT 后再开放条件格式/验证/高级表格。

P1 设计约束：每个原子节点持有独立 nodeId + kind + 稳定 userId/documentId/assetId + 必要 label 回退；站内链接为相对路径，外链仅安全协议。宿主渲染/用户查询/资产鉴权不持久化。插入令牌绑定 epoch、sheet/row/col 身份、单格内容 revision 与原生范围；异步返回若 revision/目标/编辑入口已变化，明确取消或要求用户恢复原目标，不能插入“新的当前格”。同格并发采用整个内容寄存器赢家时，丢失胜者外的编辑须按该语义通知，不许冒称自动字符合并。

P1 验收必须走安装包的原生输入：中文 IME、双 @ 与所有对象混排、左右移动/跨对象范围、Backspace/Delete、剪切/复制/内外粘贴、多文件有序上传与失败重试、Esc、公式栏往返、只读、双会话、checkpoint/重连。公式格与富文本格互斥，转换必须显式确认；文件交换可输出可读回退与 warnings，但在线保存/复制不得抹去身份。以上尚未交付。

## 宿主接入

保持一个平台注入的 session/resources，`showHeader={false}` / `showSaveState={false}`，宿主固定头部；评论动作走 menus。见包内 `examples/doca-host.tsx` 和 `examples/office-acceptance.tsx`。后者 BroadcastChannel/localStorage 是隔离验收夹具，**不是**生产连接、持久 outbox 或 ACK 实现。断线/重复 ACK 的现有 transport 单元测试不替代 Doca 联合验收。
