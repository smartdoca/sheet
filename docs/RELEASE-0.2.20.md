# 0.2.20 自动行高测量防护与静默命令失败上报

修复第一列无法拖动调整列宽的问题。固定 0.25 版本的自动行高测量在退化富文本（带有序列表 bullet、文档骨架产出空 pages 的单元格）上抛 `TypeError`：列宽命令在写入宽度**之前**先测量锚点列，一个坏单元格就让整个命令静默失败（async 命令链的拒绝无人捕获，手势看起来无效）。0.2.20 在 `SpreadsheetSkeleton.calculateAutoHeightForCell` 唯一测量入口加防护，测量失败时回退到调用方各自的默认值，并在与本地命令相关的未处理拒绝出现时给出一次警告 toast、控制台输出完整堆栈（`nativeRejectionReporter`，与命令相关联、按消息 30 秒去重、只报本地命令）。

公开 API、依赖、工作簿数据、schema、baseline、epoch、checkpoint 与宿主保存通道不变；防护只改变失败路径的行为（回退默认行高），不读取或改写任何单元格数据。

本地 `npm run build` 通过；`vitest run src` 为 187 通过、1 跳过（新增 5 个用例：测量防护、延迟渲染器接入、重试计时器、拒绝上报关联/去重/过滤）。新增隔离验收页 `examples/column-resize-acceptance.tsx`（`?column-resize-test=1`，种子工作簿含逐字复刻的退化富文本），以源码入口、0.2.19 dist 对照、0.2.20 dist 正式入口各执行一轮：0.2.19 下 A 列调宽命令失败并复现同款 TypeError、B 列成功但崩溃仍在；0.2.20 两个入口 A 列 96→176、B 列 96→136 均生效且 errors/rejections 为空，初始渲染也不再出现未捕获崩溃；命令后注入未处理拒绝出现警告 toast。真实拖拽手势未在该极简验收装置上重放（画布指针事件未达），但手势链路已在线上文档单独验证：拖拽发出的 `delta-column-width` 命令参数正确，失败点即本次防护的测量函数。以上为发布前验证；Doca 网站集成和部署另行确认。
