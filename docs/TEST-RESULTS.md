## Chrome 实际双页验收

使用本地隔离房间 `acceptance-20260911-v1`，固定 userId、不同 sessionId，真实两个 Chrome 标签页和两套 Univer 实例。测试数据不属于 Doca 用户文档。示例使用 BroadcastChannel，因此不代表后端服务器、断线/ACK 或持久离线队列已验收。

- 双页都可编辑；一页 B1 输入后本地提交 1，另一页收到后本地提交保持 0。第二页 C1 编辑生成自身 1 次提交。
- 模型查找找到 `acceptance` 所在单元格；批量替换为 `replaced` 新增 1 次本地事务；会话撤销恢复 `acceptance`，未抹除另一页 B1 内容。
- 编辑开始/结束各有事件；只读切换后输入尝试没有修改表格或增加本地提交；切换既有工作表不新增内容提交。
- 两页测试定位并修复了两个真实问题：工作簿级回调没有透传执行来源，改用正式 Event.CommandExecuted；首次画布挂载前过早刷新，改为画布就绪后刷新。
- UI 标题由宿主提供；包标题和保存提示均隐藏，固定头部下表格占满空间。
- 最终版本 Chrome 会话 ddfb0b 从 22:50:59 开始静置超过 60 秒；随后切换 Sheet2、选择 C3、滚动到 84 行附近并切为只读，本地提交仍为 0，sessionId 未变化。没有清空用户文档或重新挂载来归零。

## 明确未通过或未完成的验收

- 行列插删、合并拆分、排序筛选、工作表结构：新会话明确禁止，未交付可靠协同实现。
- 永久评论插删跟随、范围部分删除/完全删除、跨 epoch 锚点迁移：未完成。已验证的是固定结构内锚点与同 epoch checkpoint/二进制压缩后稳定。
- 两个真实页面的同格“同时输入”竞争使用自动双副本测试补充；Chrome 手工验证的是双向编辑和无回声，不冒充精确同时输入实验。
- 远端用户名/边框的滚动、缩放、冻结组合尚未完成完整浏览器矩阵；接口已提供，只读绘制限制在代码中执行。

- 断线重连、ACK 丢失/重复/延迟、IndexedDB 恢复、关闭重开后的持久 outbox、撤权/禁用/匿名/伪造身份：与 Doca 平台联合验收。旧 transport 单元测试不能替代现有 Doca 服务端验收。

## 联合验收约定

平台只订阅 `session.onLocalTransaction` 入队，并保持原 messageId/bytes；数据库 commit 后才返回同 epoch/id 的 ACK。sync-response 只补状态，不清队列。未知/重复 ACK 不得误清后续项。epoch/schema 错配暂停旧队列、允许恢复导出，不自动套用新基线。持久化后先恢复原 epoch 本地数据，再开放编辑；每个页面以服务端 sessionId 区分。平台负责真实角色、资源和 presence ACL。

包不创建模拟 ACK 来证明已保存。若 Doca 希望开放矩阵中禁止的结构操作，应先补齐模型、投影、撤销、评论锚点和逐操作并发测试，再升级 codec/schema 并共同验收。
